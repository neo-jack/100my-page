---
title: CI/CD 流水线
---

主页、二维导航、AI 后端、代码实验室和前端监控各自维护发布流程。各项目的改动由对应流水线检查与发布，减少跨服务影响。

## 先检查，再生成发布产物

3D 页面的 GitHub Actions 根据分支和改动路径触发。拉取请求执行检查；主分支推送或手动触发满足条件时，才继续发布。

检查包括部署脚本、类型检查、相关回归测试和生产边界验证。Vite 构建后再审计发布资源，确认资源完整，并排除内部维护文件。

## 使用版本化镜像部署

通过检查的构建产物打包成 Docker 镜像，使用提交 SHA 标记版本并推送到 GHCR。服务器拉取对应镜像，再替换当前项目的容器。

发布脚本带有项目范围内的回滚处理：新版本检查失败时恢复旧容器，避免一次主页发布重建所有关联服务。回滚仍依赖旧容器和运行环境可用，不能替代数据备份。

具体版本是否发布成功，以该次 Actions 记录和部署后的访问检查为准。
